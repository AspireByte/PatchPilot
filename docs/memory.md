# 原生长期记忆

长期记忆保存可跨会话复用的偏好、项目事实、决策和经验。历史压缩继续负责当前会话的发送视图，两者共享上下文预算，原始消息不会被记忆内容替换。

## 开启与存储

下面的命令通过 `--project` 定位 myagent，可从其他目录启动。`--repo` 指定需要操作的仓库；API 配置可通过环境变量或显式添加 `--env-file D:\code\My-agent\.env` 加载。

```powershell
uv run --project D:\code\My-agent --locked myagent chat --repo D:\code\My-agent --allow-api --memory

# 自定义数据库；--memory-db 本身不启用记忆
uv run --project D:\code\My-agent --locked myagent chat --repo D:\code\My-agent --allow-api --memory --memory-db D:\data\myagent\memory.sqlite3
```

默认数据库为 `~/.patchpilot/memory.sqlite3`，Windows 的 `~` 指当前用户目录。首次启用才创建数据库，无需新增依赖或启动服务。恢复会话时必须再次传入 `--memory`；`/new` 复用本次数据库及配置。

全局仅保存用户明确表达的偏好。项目事实、决策和经验按规范化绝对仓库路径的 SHA-256 隔离；Windows 路径忽略大小写。目录迁移后属于新项目，首版不自动合并不同路径或 Git worktree。

数据库使用 SQLite WAL。备份时应先关闭使用该库的会话，或使用 SQLite 的在线备份功能，不要只复制正在写入的主数据库而忽略 WAL。建议把数据库放在代码仓库之外。

## 命令与工具

| 命令 | 用途 |
| --- | --- |
| `/memory` | 显示数据库、数量、处理水位、待处理消息、用量及最近错误 |
| `/memory search 压缩` | 检索当前项目及全局偏好 |
| `/memory show <id>` | 显示完整正文、版本和来源 |
| `/memory remember --global 始终使用中文解释` | 显式记录全局偏好 |
| `/memory remember --kind decision 使用原生上下文压缩` | 显式记录项目决策 |
| `/memory forget <id>` | 停止召回该主题，保留原会话、来源和修订 |
| `/memory extract` | 使用新的操作预算处理当前会话的一批待提取原文 |

人工记录的项目默认类型为 `project_fact`。`--kind` 支持 `preference`、`project_fact`、`decision`、`experience`；`--global` 仅允许 `preference`。同范围、类型、主题的显式重复记录会更新原记录，保留版本历史。

模型仅获得 `memory_search` 和 `memory_read` 两个只读工具，无法通过工具直接写入、删除或选择其他项目。`memory_read` 支持 `offset` 和 `limit`（最大 4000 字符），有下一页时返回 `next_offset`。检索得到的记忆及工具结果会标注为历史数据，不能授予文件或命令权限。

删除使用主题墓碑，迟到批次不会自动恢复同一主题。再次显式记录同一主题可以恢复记录。“忘记”不删除原始聊天或修订，也不保证模型从不同措辞中永远不会再次提取相关信息。

## 自动提取与召回

正常完成一次输入后，先保存原始会话，再同步处理一批待提取内容。同一次提交中的目标续跑不反复提取。每次提交最多新增一次模型请求，复用工作模型，不提供工具，并严格校验 JSON、来源引用、更新目标及版本。

提取优先保留稳定信息，可能输出空操作。长消息按可见内容分片，记录消息位置、片段偏移和原文 SHA-256；每个请求默认最多 24000 字符，并服从本轮上下文限制。只处理本次给出的片段，不把压缩摘要当作原始证据。thinking、签名及记忆工具的回流结果不进入新证据。常见凭据赋值和私钥会尝试隐藏；此功能不应被当作完备的秘密检测器。

提取请求共享本轮调用次数、已知 token、超时和取消预算，独立记录于 `stats.memory`。失败或预算不足不改变已完成回答及目标状态，不推进水位；已发生的模型费用不会回滚。后续正常轮次或 `/memory extract` 可以重试。取消后不追加提取，关闭会话不调用模型。

首次为旧会话开启记忆，从启用后的新内容开始；以前启用过的会话按数据库水位继续。首版不扫描或批量导入其他历史会话。来源原文发生变化时拒绝继续，以免引用错误。片段偏移针对隐藏常见凭据后的可见文本，来源摘要值则绑定完整原始消息，可用相同投影过程追溯片段。

每次输入读取一次召回结果并冻结：最多 5 条全局偏好，显式记录优先；最多 5 条项目匹配，按 BM25、更新时间和 ID 排序。中文使用二元切分，英文支持完整标识符及驼峰拆分，单字查询使用子串检索。它不能保证召回同义改写，首版不包含语义向量检索。

注入上限为 6000 字符和本轮上下文预算 10% 中的较小者，包含序列化和来源开销。空间不足时先减少低排名项目结果，再减少偏好。正文通过只读工具按需读取。工作模型与目标评估器使用同一份快照；历史“检查通过”仍需在当前工作区重新验证。

## 实现与一致性

`core.memory` 定义数据、后端协议及不可变快照；`session_runtime.memory` 协调提取、校验、命令及工具；`infrastructure.persistence.memory_store` 负责 SQLite 和全文索引。

数据库独立维护 schema 版本。原子事务同时提交记忆、全文索引、修订、批次标识及处理水位；重放已提交批次不会重复写入，版本冲突整批回滚。来源区分用户陈述、当时工具观察和未经验证；成功经验需要引用当时成功的命令或 Harness 证据，这仍不能保证模型对语义的判断完全正确。

会话继续使用 `version: 1`，`stats.memory` 缺失时默认为零。记忆正文、提取水位和索引保存在独立数据库，自动召回快照不追加进原始 `messages`。显式调用记忆工具的结果按普通工具结果保存，但不作为新的提取证据。数据库不可用时显示明确状态，继续普通聊天。

## 验证与真实模型验收

离线测试使用临时数据库和脚本模型，不调用付费 API。覆盖跨会话/项目隔离、中文检索、更新与删除、幂等和原子性、来源校验、预算、取消、恢复、数据库锁定，以及工作模型与评估器的快照一致性。

真实模型效果需另外测量，建议使用独立数据库完成以下实验：

1. 开启 `--memory`，明确给出中文回复偏好和一条项目决策；回答后用 `/memory search`、`show` 查看实际提取内容、来源和用量。
2. 使用 `/new`，询问相关决策，观察回答是否使用正确记忆；换到另一个仓库，检查只共享全局偏好。
3. 修改偏好，核对是否更新原 ID 和版本；忘记一条记录，检查后续召回。
4. 在一次已失败检查后询问结果，核对记忆是否保留失败证据；修改代码后再次询问，不能把旧成功记录当作本次通过。
5. 记录提取准确性、召回命中与误召回、维护延迟，以及 `stats.memory` 的调用和 token 用量。用量未知时保留未知状态。

离线测试通过只证明协议和程序行为；真实模型验收结果应单独报告，不能由脚本替身推断。
