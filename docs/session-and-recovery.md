# 会话、目标与恢复

## 1. 会话保存什么

`SessionStore` 为每个会话建立独立目录，状态采用临时文件替换保存，同一会话禁止并发打开。状态中包含：

- 完整 user / assistant / tool_use / tool_result 消息；
- 当前仓库路径、模型、权限相关 Harness 元数据；
- 工作模型和评估模型的调用次数、token 和未知用量计数；
- Goal Loop 条件、状态、评估次数和暂停原因；
- 文件工具首次修改前内容和事件记录。

`events.jsonl` 记录模型、工具、目标、命令和 Harness 的开始/结束事件。大型检查日志放在会话产物目录，消息中只保存有界结果摘要。

## 2. 恢复流程

```text
读取 state.json
  -> 校验版本和会话锁
  -> 核对仓库路径
  -> 恢复完整消息与统计
  -> 目标改为 paused
  -> 清空旧文件读取授权
  -> 未完成工具调用补记中断结果
  -> 等待用户下一次输入
```

恢复不会自动重放旧命令或 Harness 检查。命令和 Harness 权限需要本次启动重新授权；修改文件前必须重新读取，避免把旧摘要当作当前版本。已发生的磁盘修改不会被恢复流程清理。

## 3. 取消与未知结果

取消可能发生在模型请求、工具调用、宿主进程或 Harness 容器期间。控制信号会向下传递，执行器尽力停止进程树或容器；如果副作用已经发生，系统保留它并把本轮标记为暂停或中断。

如果进程在工具已经启动但结果尚未落盘时退出，恢复只补记“结果未知”，不会假装成功，也不会自动重放产生副作用的动作。用户可以重新读取文件或显式再次请求检查。

## 4. 上下文边界

`core.context.ContextBuilder` 负责统一追加消息，以及在请求模型前估算系统提示词、工具定义和完整消息是否超过字符上限。当前不会自动压缩或静默删历史；达到上限时提示用户使用 `/new`。

未来的 `compact()` 应该接在这个边界内，并继续保存完整原始消息，使摘要只影响后续模型上下文，不破坏会话恢复和工具调用配对格式。

## 5. `/new` 与 `/exit`

`/new` 创建新会话但保留磁盘上的代码修改；`/exit` 保存当前状态后退出。`/status` 查看会话、目标和用量，`/diff` 查看本会话文件工具产生的差异，`/help` 查看交互命令。
