# 面经：PatchPilot · Agent 研发

> 以下为目标简历与学习口播，供掌握后选用。分析范围：2026-11-10 当前工作区的本地代码 Agent、上下文与记忆、代码验证、内部任务服务和评测，基线为 HEAD `90f81c2` 加未提交实现。

## 项目简介（简历可用）

基于 Python 与大模型工具调用构建的本地代码 Agent，支持仓库持续对话、受控文件修改、按需代码检查，以及带共享预算的目标续跑。通过原始历史留存、上下文压缩、增量长期记忆和独立补丁验收管理长任务，并提供带租约与检查点的内部任务服务。

## 简历 bullet

- **可控 Agent 执行与目标续跑：** 将模型决策与工具执行分离，宿主校验调用协议、串行执行工具并保存配对结果；显式目标激活后由无工具评估器判断执行证据，证据不足时继续工作循环，工作、评估和辅助请求共享模型次数、已知 token 与总时限。
- **工具授权与版本校验：** 启动时按授权组合工具，执行时复核权限、参数和仓库路径；文件覆盖同时检查预期摘要与本次读取版本，冲突要求重读，同目录临时文件替换避免半份写入，首次修改前保留内容基线用于差异展示。
- **原始历史与压缩视图：** 保留完整会话与可引用摘要块，仅折叠旧完整轮次，保护最近消息和未完成工具往返；摘要先暂存、校验后提交，工作模型与目标评估共用压缩历史，恢复时校验原文引用，为缺失工具结果补未知状态且不重放副作用。
- **增量长期记忆：** 按项目范围与全局偏好组织跨会话记忆，每轮生成有界召回快照，正文按需读取；回答后从原始消息分片提取，校验来源、成功证据和更新版本，将记忆、索引、修订、批次与提取游标在 SQLite 事务内一起提交，提取异常保留已完成回答。
- **代码验证与可复核评测：** 在仓库副本运行已登记检查并记录快照、执行环境与结果；固定任务从基线重建、应用候选补丁并通过独立用例验收，评测以全部计划尝试为主分母，对版本不匹配的配对单列统计，缺失用量或定价时保留未知费用。
- **租约任务调度：** 采用 PostgreSQL 短事务领取任务，以当前执行尝试、随机凭证和数据库时钟租约校验后续写入；Worker 心跳驱动合作式取消，完整工具批次边界保存补丁检查点，失联回收后经显式重启恢复候选代码，旧尝试无法提交新的数据库状态。

## 面试问题

### Q1 项目定位与架构

- 对应支柱：简介
- 触发依据：“本地代码 Agent”“持续对话”“内部任务服务”
- 考查目标：能否讲清服务对象、Agent 的工程边界与实际运行形态。
- 学习入口：[C01 入口与架构](../guide-agent/01-入口与架构.md)

**面试官问题**：用一两分钟介绍这个项目，为什么它需要一个 Agent 运行时？

**口播版**：我围绕开发者在本地仓库持续改代码这个场景组织项目。用户给出需求，模型提出读文件、改文件或运行检查的请求，但真正执行的是宿主。会话层保留历史和目标，核心循环负责模型与工具往返，工具层负责权限、参数和版本检查，基础设施负责存储、进程与验证。这样模型可以灵活决定下一步，动作能否发生以及发生后有什么证据仍由程序控制。长任务还需要压缩历史和跨会话记忆。内部服务把固定修复任务放进队列，由独立 Worker 执行；批量评测则用独立验收和固定计划比较结果。当前公开聊天与内部固定任务仍是两条循环，我会明确说明这条边界。

**追问 1**：你说模型提动作、宿主来执行，和直接让模型生成脚本有什么区别？

**触发依据**：主回答“动作能否发生以及发生后有什么证据仍由程序控制”。

**口播版**：我把动作限制在已开放的工具契约里，每次执行前检查参数、路径和版本，执行后保存结构化结果并重新交给模型。直接运行整段生成脚本很难在中间建立这些细粒度边界。不过一旦显式允许宿主命令，脚本仍拥有宿主能力，因此不能把文件工具的路径约束扩展成对命令的沙箱保证。

**追问 2**：既然有两条循环，如果重新设计你会怎样统一？

**触发依据**：主回答“公开聊天与内部固定任务仍是两条循环”。

**口播版**：现在回看，我会先统一模型消息、工具结果、预算和事件契约，再把固定任务的输入组装、补丁导出和验收作为外层策略。恢复也要保留差异：聊天恢复完整历史，服务检查点只恢复候选代码。统一的价值是减少协议处理漂移，风险是把两种生命周期强行揉在一起；这属于演进方案，当前没有完成统一。

### Q2 可控 Agent 循环与目标续跑

- 对应支柱：B1
- 触发依据：“串行执行工具并保存配对结果”“无工具评估器”“共享模型次数、已知 token 与总时限”
- 考查目标：工具协议、状态机、成本边界与取消传播。
- 学习入口：[C02 模型与工具循环](../guide-agent/02-模型与工具循环.md)、[C07 目标续跑与共享预算](../guide-agent/07-目标续跑与共享预算.md)

**面试官问题**：模型怎样驱动工具，目标没有完成时为什么还能继续，而且不会无限执行？

**口播版**：我用宿主循环承接模型返回的动作请求。响应先检查工具编号并保存请求，再检查停止原因与工具块是否一致，随后按顺序执行并保存每个配对结果，最后继续请求模型。普通聊天结束就返回；只有用户显式设置目标，工作模型结束后才调用一个没有工具的评估器，依据当前对话和执行结果判断。证据不足且仍可继续时，把缺失证据反馈给工作循环。整个提交共享模型次数、工具次数、已知 token 和总时限，还有重复动作与续跑次数限制。评估协议不合法、目标不可验证、预算耗尽或用户取消时，都会暂停并保留状态。

**追问 1**：评估器也用模型，怎样防止它只是相信助手说“完成了”？

**触发依据**：主回答“依据当前对话和执行结果判断”。

**口播版**：我要求它看实际工具证据，区分调用成功和检查通过，也要核对检查对应的代码版本与执行环境。返回值是严格 JSON，只有明确达成才更新目标状态。不过格式正确仍不代表判断正确，所以目标评估只用于本地续跑决策；真正的固定任务成绩另走独立补丁验收。

**追问 2**：自动摘要和记忆提取会不会绕过你说的预算？

**触发依据**：B1“辅助请求共享…”以及上一个主回答“整个提交共享模型次数”。

**口播版**：它们都要经过计数边界。循环内的摘要走辅助模型请求，会话层通过事件同步统计；目标评估和回答后的自动记忆提取也计入本轮。时间用同一个单调时钟起点，向下传剩余时限。已知 token 阈值只能控制已收到的 usage，未知用量会单独保留，不能宣称精确金额硬上限。

**追问 3**：用户取消时，命令会马上停止且修改全部回滚吗？

**触发依据**：主回答“用户取消时…暂停并保留状态”。

**口播版**：取消是合作式传播。模型网络请求有监视任务，进程执行器轮询停止信号并清理进程树，输出也保留有界尾部。但检测存在间隔，已经执行的文件修改不会回滚，服务端已处理的模型请求也可能产生费用。恢复时需要依据当前文件重新确认进度。

### Q3 工具授权与文件版本

- 对应支柱：B2
- 触发依据：“启动时按授权组合工具”“预期摘要与本次读取版本”“同目录临时文件替换”
- 考查目标：能力授权、乐观并发与文件写入的保证范围。
- 学习入口：[C03 工具授权与文件修改](../guide-agent/03-工具授权与文件修改.md)

**面试官问题**：怎样控制工具权限，避免模型覆盖用户刚修改的文件？

**口播版**：我把工具描述和实际执行检查都做在宿主。没有授权的命令工具不会出现在定义里，即使模型伪造调用，执行入口仍会拒绝。文件工具校验仓库相对路径并拒绝越界和链接。修改已有文件必须先读，写入时同时比较当前内容摘要、调用携带的预期摘要，以及本次进程记录的读取版本。用户在中间改过文件就返回冲突，要求重新读取。首次修改前保存基线供 diff 使用，覆盖时用同目录临时文件替换，成功后清除旧读取授权。

**追问 1**：检查摘要后再替换，就完全没有并发覆盖了吗？

**触发依据**：主回答“写入时同时比较…”“临时文件替换”。

**口播版**：还不能这样保证。写前会再次比较字节，但最后一次检查和替换之间仍有窗口。原子替换避免半份内容，不是原子比较交换。这个方案适合本地协作，检测大部分过期写入；如果要求强并发一致，需要受控工作区或所有参与者遵守的锁协议。

**追问 2**：路径已经限定在仓库里，为什么还要单独区分命令权限？

**触发依据**：主回答“文件工具校验仓库相对路径”。

**口播版**：因为路径函数只约束文件工具。宿主命令可以访问当前用户能访问的其他文件和网络，不能继承这个限制。按需检查工具只允许选择启动时登记的命令配置，但宿主执行依然需要信任项目代码；需要隔离时要使用明确的容器后端。

### Q4 长会话的压缩与恢复

- 对应支柱：B3
- 触发依据：“保留完整会话”“仅折叠旧完整轮次”“摘要先暂存”“不重放副作用”
- 考查目标：上下文管理、工具协议边界、摘要失败与崩溃恢复。
- 学习入口：[C04 会话持久化与恢复](../guide-agent/04-会话持久化与恢复.md)、[C05 上下文压缩](../guide-agent/05-上下文压缩.md)

**面试官问题**：长会话怎样压缩，并在中断后可靠地继续？

**口播版**：我把完整原始历史和模型实际看到的视图分开。请求前先扣掉固定提示、工具定义和记忆来源的开销，接近可用历史预算时，只对旧完整轮次生成摘要。摘要块绑定原始范围与内容哈希，最近消息、当前用户轮和没完成的工具往返保持原样。新摘要先暂存，检查有效且能缩小视图后才提交；失败保留原文和已有摘要。会话把这些状态保存下来，恢复时核对摘要引用。若工具执行过但结果没来得及保存，我会补“结果未知”，要求重新检查当前状态，不自动重放命令。

**追问 1**：为什么不能按最近 N 条消息直接截断？

**触发依据**：主回答“旧完整轮次”“没完成的工具往返保持原样”。

**口播版**：工具结果也属于用户角色消息，任意截断可能只留下调用或只留下结果。当前做法用未完成工具 ID 集合跟踪往返，只有进入新的普通用户消息且没有待返回工具时才形成旧轮次边界，再结合最近消息保护窗口。这样保持协议完整，也避免把当前仍在解决的问题提前折叠。

**追问 2**：如果超限内容都在最近轮次里，压缩还能救回来吗？

**触发依据**：上一回答“最近消息保护窗口”。

**口播版**：不能保证。如果没有合法旧边界，或者固定提示和受保护尾部已经超过预算，就停止并保留状态。默认 80% 触发、60% 目标作用在可用历史预算上，目标是软目标，最终上限是硬检查。这里按序列化字符计量，不是精确 tokenizer 计量。

**追问 3**：保存了状态，为什么不能把缺失结果的工具再执行一次？

**触发依据**：主回答“结果没来得及保存”“不自动重放命令”。

**口播版**：副作用和保存历史之间不在一个事务里。命令可能已经改了文件甚至调用了外部系统，只是结果记录缺失；重放可能重复执行。原子状态文件替换只防半份 JSON，无法消除这个窗口。所以恢复先承认未知，再观察当前状态；要自动重试远端动作，需要额外业务幂等协议。

### Q5 长期记忆的来源与事务

- 对应支柱：B4
- 触发依据：“每轮生成有界召回快照”“从原始消息分片提取”“批次与提取游标…一起提交”
- 考查目标：跨会话记忆生命周期、来源质量、事务和幂等。
- 学习入口：[C06 长期记忆](../guide-agent/06-长期记忆.md)

**面试官问题**：长期记忆什么时候读写，怎样避免重复和错误记忆？

**口播版**：我在输入后召回全局偏好和当前项目相关记录，固定一份有界快照，给工作模型和评估器共用；正文通过只读工具按需读取。回答完成后，再从未处理的原始消息分片提取一批记忆。每条候选必须引用本批来源，偏好来自用户明确陈述，成功经验需要当时成功的工具证据。存储按主题和版本更新，把记录、索引、修订、批次和游标放在一个 SQLite 事务里，重复批次直接跳过，版本或水位冲突整批回滚。提取失败记录错误并保留水位，不影响已经完成的回答。

**追问 1**：为什么从原始消息提取，而不是直接从压缩摘要里提取？

**触发依据**：主回答“从未处理的原始消息分片提取”。

**口播版**：摘要是有损的，可能省略工具失败、条件和来源。原始消息能保留稳定引用和内容哈希，长消息按消息、片段和偏移推进。推理块和记忆检索回流不当新来源，避免记忆不断引用自己。当前每次只处理一批，未处理部分留在后续水位，不是无限后台抽取。

**追问 2**：事务能解决什么，不能解决什么？

**触发依据**：主回答“放在一个 SQLite 事务里”。

**口播版**：它保证要么记录、索引、修订和游标都更新，要么都不更新，避免记录写了但水位没前进导致重复。重复批次在比对旧游标之前拦截，所以已提交批次重放可以安全返回。它不覆盖会话 JSON 和模型调用，也不能保证自然语言提取全对；来源检查只是降低错误升级为长期事实的概率。

**追问 3**：记忆检索依靠什么？用户要求删除一条旧记忆时怎样处理？

**触发依据**：B4“按项目范围与全局偏好组织”及主回答“召回…记录”“版本更新”。

**口播版**：当前是词法全文检索，用中文相邻二元词和英文标识符拆词，再由 FTS5 排序，没有向量召回。遗忘是删除状态和索引移除，保留墓碑与修订，防止迟到自动批次复活；原会话也还在，当前已固定的快照不因此重建。需要物理清除时必须另定义数据删除范围。

### Q6 检查结果怎样成为证据

- 对应支柱：B5
- 触发依据：“仓库副本”“快照、执行环境与结果”“固定任务从基线重建”
- 考查目标：输入版本绑定、隔离与检查覆盖的保证范围。
- 学习入口：[C08 代码验证与证据](../guide-agent/08-代码验证与证据.md)、[C10 评测与工程质量](../guide-agent/10-评测与工程质量.md)

**面试官问题**：Agent 说代码修好了，你怎样确认检查结果足够可信？

**口播版**：我先区分模型自述、工具调用成功和实际检查通过。项目检查只能选已登记配置，把当前代码复制到临时快照，记录快照摘要、执行命令、环境、退出码和日志；结果明确标宿主或容器证据。固定任务进一步从基线重建，应用交付补丁，再运行维护者独立用例，并核对候选和验收版本没有变化。这样结论能对应到输入和环境，也能检查补丁是否可复现。但通过有限检查只能支持覆盖范围内的结论，后续改代码需要新的检查。

**追问 1**：在副本里执行就安全了吗，Docker 不可用时怎么办？

**触发依据**：主回答“临时快照”“宿主或容器证据”。

**口播版**：副本只是避免直接把测试写入当前目录，宿主进程仍有宿主权限。容器后端才增加无网络、非 root 和资源限制。当前默认宿主；显式要求容器时不可用就报基础设施错误。只有自动模式且允许降级，预检不可用才转宿主，并明确标注降级，不能拿它满足隔离目标。

**追问 2**：快照摘要能证明代码与检查一致到什么程度？

**触发依据**：主回答“结论能对应到输入和环境”。

**口播版**：它标识实际复制出的输入，不保证复制过程中整个源目录在同一时刻原子一致。固定任务验收还会执行后核对候选和用例摘要，发现变化就不给正常通过。摘要能证明版本身份，不能证明测试覆盖完整或代码没有逻辑缺陷，这需要独立用例设计和进一步评测。

### Q7 Agent 评测怎样避免自我证明

- 对应支柱：B5
- 触发依据：“独立用例验收”“全部计划尝试为主分母”“版本不匹配的配对单列”“未知费用”
- 考查目标：评测设计、选择偏差、对照可比性与成本口径。
- 学习入口：[C08 代码验证与证据](../guide-agent/08-代码验证与证据.md)、[C10 评测与工程质量](../guide-agent/10-评测与工程质量.md)

**面试官问题**：你会怎样衡量这个 Agent 的效果，避免只展示成功案例？

**口播版**：我先保存完整尝试计划，按任务、策略和重复位置记录每次结果，失败与未完成都保留在端到端成功率的分母。生成侧只能读公开材料，最终用独立补丁验收。对照采用固定检索后一次生成，与有工具反馈循环的 Agent 比较，还要核对任务、验收、镜像、代码、配置和实际模型版本。环境错误单列原因，可评分的同条件配对另算胜负。费用按显式版本价格和已知用量估算，缺用量或价格就保持未知。当前有这些机制和测试代码，材料没有真实模型成绩或线上收益数字。

**追问 1**：环境问题为什么要算失败，不会低估模型能力吗？

**触发依据**：主回答“失败与未完成都保留在端到端成功率的分母”。

**口播版**：端到端指标回答用户最终有没有拿到结果，环境失败确实影响体验，所以必须保留。模型条件能力是另一问题，可以在可评分子集单列，但要同时报告子集大小和筛选原因。把环境错误直接删掉再称整体成功率，会掩盖系统可靠性；把不可比配对算模型输赢也同样不合理。

**追问 2**：成本降低该怎样计算？

**触发依据**：主回答“显式版本价格和已知用量估算”。

**口播版**：我会分别看单次尝试费用、成功尝试平均费用，以及总尝试费用除以成功数。最后一个包含失败成本，更接近获得一个成功结果的代价。缓存输入也要按相应单价计，缺失不能当免费。只有同条件、完整用量的对照才能讨论降低比例，当前不能仅凭有压缩机制就报节省百分比。

**追问 3**：如果要证明记忆和压缩有效，下一步怎样做？

**触发依据**：上一回答“不能仅凭有压缩机制就报节省百分比”。

**口播版**：我会在同模型、任务、预算和验收版本下做开关对照，记录最终验收、约束遗失、token、耗时和未知用量。长任务还要覆盖摘要反复合并与历史结论变化，观察记忆是否引入过期事实。这是后续方案；小样本合成任务的描述统计不能直接外推生产收益或显著性。

### Q8 Worker 失联后的提交权

- 对应支柱：B6
- 触发依据：“数据库时钟租约”“补丁检查点”“显式重启”“旧尝试无法提交”
- 考查目标：领取事务、租约、过期写入、取消与检查点恢复边界。
- 学习入口：[C09 任务服务与租约](../guide-agent/09-任务服务与租约.md)

**面试官问题**：Worker 失联后又返回成功结果，怎样防止它污染当前状态？

**口播版**：我把一次运行和每次执行尝试分开。领取在短事务里锁住队列项、创建尝试并设置租约，长任务执行期间通过心跳续租。后续每次写入都锁定运行和尝试，检查当前尝试身份、Worker、随机凭证、状态以及数据库时间下的租约。只要过期或者运行已经切换到新尝试，旧 Worker 就无权写入。过期回收将任务标为中断，显式重启才重新排队，新尝试可以从最新补丁检查点重建候选代码。最终提交也复核取消与租约，避免迟到成功覆盖有效状态。

**追问 1**：领取时用了行锁，为什么还需要租约和凭证？

**触发依据**：主回答“领取在短事务里”“后续每次写入都…检查”。

**口播版**：行锁保护的是领取瞬间，事务结束锁就释放，不能在整个模型执行过程中一直占着。跳过已锁行让其他 Worker 继续领别的任务。租约与当前尝试身份解决后续所有权，随机凭证避免仅凭任务编号冒充持有者。它不是单调递增编号，真正的约束来自组合校验。

**追问 2**：写报告时租约恰好过期，或者先取消后返回成功呢？

**触发依据**：主回答“最终提交也复核取消与租约”。

**口播版**：最终提交在锁内按有效取消状态生成报告，报告封存前检查一次，封存后再按数据库时钟检查租约，最后登记引用与终态。如果已过期，数据库事务回滚，可能留下未登记文件，但不会把它作为有效报告公开。已接受取消时迟到成功会按取消收尾。

**追问 3**：有检查点和租约后，是否能保证任务恰好执行一次？

**触发依据**：主回答“从最新补丁检查点重建候选代码”“旧 Worker…无权写入”。

**口播版**：不能。检查点恢复候选补丁与元数据，不恢复完整聊天推理或外部执行。数据库拒绝旧写入，也无法撤销失租前已经发出的模型请求、费用和其他外部副作用。若接入发布或支付等动作，需要远端幂等键、可查询状态或补偿协议，不能仅靠心跳宣称恰好一次。
