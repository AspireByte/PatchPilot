# 导学：PatchPilot

> 目标：面向 Agent 研发岗位，能沿源码解释模型决策、工具副作用、上下文、恢复和验证之间的关系。
> 水平：掌握 Python 基础、能写 CRUD；方向：Agent 研发；实际覆盖：Python 本地代码 Agent、内部任务服务与评测，无产品前端。
> 源码基线：2026-11-10，HEAD `90f81c20681a6740b498584b249a4061a5d90b11`，加当前未提交工作区。上下文压缩和长期记忆已在当前源码中实现，部分文件尚未纳入 Git；这不是纯 HEAD 版本的说明。

## 学习目标与项目地图

项目的主要使用场景是：开发者在本地仓库持续对话，由模型提出读写代码或执行检查的请求，宿主负责授权、执行、保存历史和返回证据。当前公开命令是 `myagent chat`；包名仍是 `patchpilot`。技术栈来自 [pyproject.toml](../../pyproject.toml)：Python ≥3.12、Anthropic SDK、Pydantic 2、FastAPI、SQLAlchemy 2、psycopg、Alembic；长期记忆使用标准库 SQLite 与 FTS5。

分析得到的核心工程矛盾是：模型可以生成动作，但动作是否能执行、是否已经发生、是否真的完成任务，需要由宿主状态与执行证据约束。这是对当前机制的归纳，不代表已有线上事故或正式业务指标。

| 层与入口 | 持有的职责和状态 | 主要源码 |
| --- | --- | --- |
| CLI | 参数、权限开关、模型/连接生命周期、终端展示 | [interfaces/cli/chat.py](../../src/patchpilot/interfaces/cli/chat.py) |
| 会话协调 | 原始历史、目标、摘要块、跨轮统计、文件基线、记忆快照 | [session_runtime/session.py](../../src/patchpilot/session_runtime/session.py) |
| 核心循环 | 模型与工具往返、协议检查、本轮预算和事件 | [core/loop.py](../../src/patchpilot/core/loop.py) |
| 模型与工具适配 | SDK 协议转换、注册分发、参数与路径校验 | [model/protocol.py](../../src/patchpilot/model/protocol.py)、[tools_runtime/registry.py](../../src/patchpilot/tools_runtime/registry.py) |
| 基础设施 | 会话文件、SQLite 记忆、进程清理、快照验证 | [infrastructure](../../src/patchpilot/infrastructure/__init__.py) |
| 内部任务服务 | Run/Attempt、租约、检查点、产物引用、取消与显式重启 | [service/worker.py](../../src/patchpilot/service/worker.py)、[service/repository.py](../../src/patchpilot/service/repository.py) |
| 固定任务与评测 | 独立补丁验收、计划尝试、对照统计与费用口径 | [legacy/benchmark/agent.py](../../src/patchpilot/legacy/benchmark/agent.py)、[evaluation/runner.py](../../src/patchpilot/evaluation/runner.py) |

必须区分两条执行路径：公开聊天使用 `AgentSession → AgentLoop`；任务 Worker 和批量评测仍调用 `legacy.benchmark.run_agent`。两者共享部分模型、预算和基础设施，当前没有统一成同一个循环。`SessionManager` 目前只是工厂包装，不是实际后台调度器。

四条代表链路：

1. **持续改代码**：CLI 组装 → `submit` 保存用户输入 → 核心循环请求模型 → 工具校验并执行 → 保存配对结果 → 模型结束。普通聊天不自动进行独立基准验收。
2. **长会话**：请求前扣除固定提示、工具定义和记忆快照 → 折叠旧完整轮次 → 主模型消费摘要视图；显式目标评估也使用压缩历史与同轮记忆快照，原始消息保留。
3. **跨会话记忆**：本轮输入触发有界召回 → 回答完成后从原始历史提取一批来源 → 校验结构与来源 → SQLite 同事务提交记忆、索引、版本、批次和游标。默认关闭，需启用。
4. **服务化固定任务**：API 入队 → Worker 短事务领取 → 心跳续租 → 代码副本运行 → 保存补丁检查点 → 从固定基线独立验收 → 租约校验后提交报告；过期回收后需显式重启。

## 学习重点与记忆提纲

先理解五个因果：模型提出工具调用不等于宿主已执行；落盘历史不等于文件副作用事务提交；摘要压缩不等于删除原文；历史记忆不等于当前验证；租约校验不等于外部动作恰好执行一次。

再记住三条可口述主链：`用户输入 → 模型 → 工具 → 结果 → 模型`；`原始历史 → 摘要视图/记忆快照 → 下一次请求`；`领取 → 心跳 → 检查点 → 验收 → 校验租约后提交`。分别在 [C02](../guide-agent/02-模型与工具循环.md)、[C05](../guide-agent/05-上下文压缩.md)、[C09](../guide-agent/09-任务服务与租约.md)中展开。

最后按[面经](面经.md)准备两层表达：先用通用工程语言讲职责、状态和约束，再用源码索引回答细节。材料没有性能提升百分比、真实线上成功率或已完成的模型选型实验；测试文件是行为证据线索，不自动代表本次已运行通过。[交付检查](交付检查.md)记录本次实际校验。
