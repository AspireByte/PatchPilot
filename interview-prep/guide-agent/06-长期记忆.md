# C06 长期记忆：从原文提取、按来源约束、与游标一起提交

> 课程性质：核心
> 返回：[导学](../PatchPilot/导学.md)；前置：[C04](04-会话持久化与恢复.md)、[C05](05-上下文压缩.md)；下一课：[C07](07-目标续跑与共享预算.md)。
> 对应：B4；[Q5](../PatchPilot/面经.md#q5-长期记忆的来源与事务)；目标掌握：理解机制、设计与表达。

## 本课重点

新会话需要过去的项目结论时，不恢复全部旧聊天，而是召回有界的记忆摘要，需要正文再调用只读工具。每轮输入后固定一份召回快照供工作模型与评估器共同使用；回答完成后再从尚未处理的原始历史提取一批记忆。

长期记忆默认关闭。它不是上下文压缩：压缩是当前会话的历史视图；记忆是跨会话、按项目范围组织的独立记录。当前检索使用 SQLite FTS5/BM25 和词法处理，没有 embedding 或向量数据库。

## 主链与职责

```text
submit：保存输入 → recall → 有界 MemorySnapshot → 模型/评估器
完成回答：_finish_answer → extract 原始历史片段 → 校验模型 JSON 与来源
        → apply_batch → 记忆/FTS/修订/游标/批次同事务提交
```

项目范围由规范化仓库绝对路径哈希产生；移动仓库可能得到不同 scope。全局范围只容纳偏好。SQLite 连接可由多个会话共享，库内部锁与事务串行化写入；没有自动后台无限追赶线程，每次完成回答只处理一批，剩余内容留待后续操作。

## 源码阅读

先读 [core/memory.py](../../src/patchpilot/core/memory.py) 的 `MemorySource / MemoryCursor / MemorySnapshot`；再读 [session_runtime/memory.py](../../src/patchpilot/session_runtime/memory.py) 的 `MemoryCoordinator.__init__ / recall / extract / _parts`；最后读 [memory_store.py](../../src/patchpilot/infrastructure/persistence/memory_store.py) 的 `search / _upsert / apply_batch / forget`。

游标是 `message / part / offset / digest`：一条很长的工具结果可以分片继续，摘要压缩不影响这个游标，因为提取来源始终是原始消息。首次给旧会话启用记忆，初始游标位于当前末尾，不回填之前历史；曾启用过的会话继续使用库中水位。

`extract` 每批最多收集 8 个片段，每段最多 4000 字符，并以二分法检查序列化请求是否装得下。提取请求携带有限既有记录和明确来源 ID，模型最多生成配置允许的操作数（默认 8）。更新已有记录必须提供本次可见的 ID 与版本。

## 机制与边界

工具输出按宿主记录区分当时成功、失败与未知：命令检查退出码与超时，Harness 看嵌套状态；助手自述不升级为成功证据。偏好必须来自用户明确陈述；全局写入只接受偏好。thinking 和记忆检索工具返回不作为新的提取来源，减少“记忆引用自己再当新事实”的循环。成功经验的检查是结构与规则约束，仍不是对自然语言所有语义的形式化证明。

`apply_batch` 使用 `BEGIN IMMEDIATE`，先按 scope/session/batch 去重，再核对完整起始游标、结束位置前进，随后逐条更新记录、全文索引与修订，最后写新游标和批次。任何版本冲突使整批回滚，包括已经处理的前几条更新；重复已提交批次返回 false。即使模型返回零条操作，也可提交已处理原文的水位。

遗忘将记录置 deleted 并移除 FTS 条目，保留修订和墓碑。迟到的自动提取不会复活墓碑主题，但整批仍可能推进游标；显式手工记忆可重新建立内容。因此“忘记”不代表抹除所有会话原文、历史修订或当前已固定的快照。

[HTML 专题：正常提交、重复批次、版本冲突、游标冲突](topics/C06-记忆事务.html)对比可见的库状态。SQLite 事务不覆盖 Session JSON；库提交后进程中断，恢复时通过批次和库内水位避免重复写入。

## 需要懂什么

召回快照只注入摘要和来源元数据，默认上限为 `min(6000, max_context_chars // 10)`，必要时还为当前轮保护区缩减。偏好在前、项目记录在后，超预算先移除后面的项目结果；正文通过 `memory_read` 分页读取。快照保持同轮稳定，历史结论不会自动获得执行权限或替代当前工作区检查。

提取复用主模型，和工作/评估共享本次预算。数据库锁、模型错误、非法输出等记忆异常被记录，已经完成的主回答仍可返回；游标不推进则后续仍能重试。取消工作轮不会自动抽取；提取中取消也不应提交未完成批次。脱敏采用规则，只能覆盖常见格式，不能称作完整敏感信息识别。

## 需要记住什么

- 两个时点：输入后固定召回，回答后增量提取；来源是原文，不是摘要视图。
- 一个事务：记忆、FTS、修订、游标和批次一起提交；重复批次先拦截，冲突整批回滚。
- 三个边界：历史不等于当前事实，来源约束不等于语义绝对正确，遗忘不等于物理清除全部历史。
