# C02 模型与工具循环：把动作请求变成可恢复历史

> 课程性质：核心
> 返回：[导学](../PatchPilot/导学.md)；前置：[C01](01-入口与架构.md)；下一课：[C03](03-工具授权与文件修改.md)。
> 对应：B1；[Q2](../PatchPilot/面经.md#q2-可控-agent-循环与目标续跑)；目标掌握：看懂链路、理解机制、设计与表达。

## 本课重点

模型返回“读取文件，再执行检查”时，返回值只是动作提议。宿主先校验协议，将 assistant 消息保存，再逐个执行工具并保存对应结果，最后把结果送回下一次模型请求。一个响应里的多个工具按顺序执行，当前没有并行工具调度。

`end_turn` 代表模型结束回答，不能直接推出代码修复成功。预算耗尽或协议错误则中止本轮，由 Session 转换成可恢复的暂停。

## 主链与职责

`工具定义 → 构建上下文 → 请求模型 → 校验编号 → 保存 assistant → 校验停止协议 → 建立结果列表 → 串行工具执行 → 保存 tool_result → 下一次请求`。

循环通过 checkpoint 回调保存状态；并不知道磁盘存储格式。事件用于让会话统计、CLI 展示等观察者跟随执行，不取代真实状态快照。

## 源码阅读

首先读 [core/types.py](../../src/patchpilot/core/types.py) 的 `ModelRequest`、`ModelResponse` 和 `ToolCall`，确认核心只消费普通数据。再按 [core/loop.py](../../src/patchpilot/core/loop.py) 的 `_call_model → complete_auxiliary → _run` 跟进一次往返。最后读 [tools_runtime/executor.py](../../src/patchpilot/tools_runtime/executor.py) 的 `execute`，理解普通工具异常转为结构化反馈，而取消继续向上传播。

核心的真实片段是：

```python
results: list[dict] = []
messages.append({"role": "user", "content": results})
self.checkpoint()
for block in blocks:
    # 逐个校验预算并执行，结果追加进同一个列表对象
    ...
```

这里的列表不是预先完成的结果，而是消息所引用的可变对象。执行完一个工具就追加一个带 `tool_use_id` 的结果并保存。若执行中断，历史可能已经包含调用，但还没有全部结果，恢复时由 C04 修补。

编号检查在 assistant 入历史之前：同批重复 ID 或与原始历史已有 ID 冲突都会停止，避免后续工具结果无法唯一配对。停止原因必须为 `tool_use` 或 `end_turn`，并且与有无工具 block 相符；错误响应不会执行工具。

## 机制与边界

多工具串行便于前一个工具的副作用成为后一个工具可观察的状态，也避免并行写同一文件的冲突。代价是独立读取不能并行加速。若未来并行，需要区分只读动作、文件写集合、共享预算和取消传播，不能简单把 for 改为线程池。

普通工具失败以 `ok=false` 写入结果，模型可以据此重新读取或调整；取消异常不能被吞成普通错误，否则模型可能继续请求副作用。循环对相同“工具名＋输入＋返回结果”的指纹计数，到 `max_repeated_actions` 时停止；它是重复动作保护，不保证检测所有语义死循环。

模型返回的 assistant 先保存，再检查停止协议，所以异常停止可能保留了文本与工具提议。重要的是工具尚未执行；Session 的暂停处理会补齐未知结果，不能拿历史中的提议当执行证据。

[test_runtime_core.py](../../tests/test_runtime_core.py) 包含工具配对、重复编号不执行、上下文超限不发请求和核心依赖方向检查。这里引用测试意图，不声称本次已运行这些业务测试。

## 需要懂什么

Agent 与“调用一次模型 API”的区别，在于宿主反复把可控工具的结果反馈给决策过程，并维护停止条件和状态。模型可以不确定，宿主仍必须确定哪些动作发生、哪些结果未知、哪个请求超预算。

checkpoint 有助于恢复协议状态，却没有把副作用与记录提交合为一个事务。若命令执行成功后进程崩溃，缺失结果只能标未知。工具配对是模型协议要求，恰好执行一次是更强的业务保证，两者不能互换。

## 需要记住什么

- 当前循环是单决策者、同步串行工具执行；显式目标评估在外层 Session。
- assistant 工具请求和 user 工具结果按 ID 配对，重复 ID 在执行前拦截。
- 模型结束、工具返回成功、目标达成、独立验收通过分别描述不同事实。
