# C04 会话持久化与恢复：结果缺失为什么不能重放

> 课程性质：核心
> 返回：[导学](../PatchPilot/导学.md)；前置：[C02](02-模型与工具循环.md)、[C03](03-工具授权与文件修改.md)；下一课：[C05](05-上下文压缩.md)。
> 对应：B3；[Q4](../PatchPilot/面经.md#q4-长会话的压缩与恢复)；目标掌握：理解机制、设计与表达。

## 本课重点

假设工具已经执行写文件，进程却在保存结果前退出。恢复时直接重放，可能把同一个副作用做两次；认定失败则可能忽略已经发生的修改。当前策略是保留调用，补写“结果未知”的错误结果，重新检查文件后继续，不自动重放。

会话文件的原子替换保证一次状态写入尽量完整，不覆盖仓库文件、事件日志、外部模型请求和记忆数据库的事务。操作系统文件锁保护同一会话，不能锁住整个仓库。

## 主链与职责

`取得会话独占锁 → load/解码/严格校验 → 校验仓库路径 → 重新绑定原始历史 → 暂停未完成目标 → 创建本次授权的工具 → 修补缺失结果 → 恢复摘要块并校验引用 → 保存`。

会话状态持有原文、目标、统计、文件基线、模型和 Harness 元数据以及摘要块。执行权限、读取摘要授权由本次进程重新建立。记忆提取游标另存在 SQLite 中，不属于这个 JSON。

## 源码阅读

先读 [session_store.py](../../src/patchpilot/infrastructure/persistence/session_store.py) 的 `SessionStore.__init__ / load / save / close`，再读 [state.py](../../src/patchpilot/session_runtime/state.py) 的 `StateCodec`，最后进入 [session.py](../../src/patchpilot/session_runtime/session.py) 的恢复分支、`save`、`_repair_pending` 与 `close`。

状态文件写入的真实顺序是：

```python
json.dump(self.codec.encode(state), stream, ensure_ascii=False, indent=2)
stream.flush()
os.fsync(stream.fileno())
# 退出文件上下文后
os.replace(name, self.directory / "state.json")
```

临时文件在目标同一目录，写入完成后替换正式文件，finally 清理临时产物。加载时经 Pydantic 严格校验；保存时不调用同一份字段模型校验。版本当前仍为 1，新加 compression 和统计字段提供默认值，兼容旧版没有这些字段的记录；这不表示任意未来版本都能加载。

## 机制与边界

Windows 使用 `msvcrt.locking`，其他平台使用 `flock`，锁随句柄关闭或进程退出释放。锁文件存在不代表仍被占用。同进程中的提交和手动压缩另由非阻塞获取的 `RLock` 约束；其他线程同时操作会被拒绝。可重入锁并不是对同线程回调重入的全面禁止。

`_repair_pending` 找到 assistant 的工具调用，保留已记录结果，为缺失项补错误结果；它从不执行工具。暂停和恢复都不回滚文件。对一个结果未知的命令，安全续跑的依据应是当前文件和新的检查证据。

恢复时更换 `self.messages` 列表后，同时更新 `self.context.messages` 引用，否则下一轮会向旧列表追加。这体现了状态所有权：原始历史是会话的权威记录，上下文构建器持有同一对象的引用。

`events.jsonl` 是过程记录，追加事件没有逐条 fsync，不能替代状态快照。文件保存失败、事件写入失败仍可能中止流程。独立基准服务检查点只恢复候选补丁，和本课完整聊天状态不同，见 [C09](09-任务服务与租约.md)。

[test_chat_session.py](../../tests/test_chat_session.py) 中 `test_crash_checkpoint_does_not_replay_command` 与 `test_restore_keeps_history_goal_diff_and_requires_fresh_read` 针对上述语义；它们是本次阅读的测试代码，非新执行结果。

## 需要懂什么

持久化的关键不是“存了 JSON”，而是存储时点与副作用时点之间的关系。若不能把副作用纳入同一事务，就必须承认“已经执行但结果未知”的窗口。当前通过不重放避免盲目重复，通过重新观察恢复进度，牺牲自动无缝续跑。

若未来要自动重试远程动作，需要业务幂等键、状态查询或补偿协议。单纯保存更多聊天记录，不能凭空获得远端恰好执行一次的保证。

## 需要记住什么

- 状态原子替换解决半文件；会话锁解决同会话多进程；都不解决跨系统事务。
- 未完成调用补未知结果，不自动重放；恢复目标暂停，需显式继续。
- 原始历史与基线可恢复，执行权限与读取授权重新绑定。
