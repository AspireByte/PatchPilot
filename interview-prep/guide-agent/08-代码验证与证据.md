# C08 代码验证与证据：检查通过的是哪一份输入

> 课程性质：核心
> 返回：[导学](../PatchPilot/导学.md)；前置：[C03](03-工具授权与文件修改.md)、[C07](07-目标续跑与共享预算.md)；下一课：[C09](09-任务服务与租约.md)。
> 对应：B5；[Q6](../PatchPilot/面经.md#q6-检查结果怎样成为证据)；目标掌握：理解机制、设计与表达。

## 本课重点

工具成功调用验证器，不等于测试通过；测试通过还要看执行环境与输入版本。项目检查把当前仓库复制到临时快照，运行启动时登记的 profile，返回退出状态、快照摘要和产物。它可以是宿主执行，也可以是 Docker 隔离执行。

固定任务验收则从不可变基线重建工作区、应用交付补丁并引入维护者 acceptance。两者服务不同场景，公开聊天不会因为模型结束就自动走固定任务验收。

## 主链与职责

`模型选择已登记 profile → VerificationRunner.run → 建立总 deadline → Snapshotter.copy → 确定 host/docker → 执行 → 收集状态与截断标记 → 清理 → 写 manifest/profile/output/result → 返回嵌套 harness 结果`。

配置是启动时控制面，工具只选 profile 名称，不能在调用里新增命令。快照减少检查对当前仓库的直接扰动，但宿主代码仍有宿主权限。

## 源码阅读

读 [verification/config.py](../../src/patchpilot/infrastructure/verification/config.py) 的 `HarnessConfig.load / _argv / _cwd`，再读 [verification/runner.py](../../src/patchpilot/infrastructure/verification/runner.py) 的 `Snapshotter.copy → VerificationRunner.run → HostBackend/DockerBackend → ArtifactWriter.write`。

快照摘要来自实际复制的文件路径、内容哈希和模式排序列表，标识本次输入。复制过滤凭据、依赖、缓存、维护者材料，拒绝链接，并限制文件数/体积。复制不是仓库级原子快照：其他进程可在遍历期间修改不同文件，因此摘要证明的是复制出的内容，不能推出整个源目录曾在某一时刻原子一致。

对比 [legacy/benchmark/verification.py](../../src/patchpilot/legacy/benchmark/verification.py) 的 `verify_benchmark`：它记录补丁、基线、候选与验收摘要，执行后重新核对候选和验收版本。这里验的是补丁从基线能否重建和通过独立用例。

## 机制与边界

当前默认 runtime 为 host；只有 auto 且允许 fallback 时，Docker 预检不可用才按授权降级。显式 docker 不可用会给基础设施错误，不能自动降成宿主。Docker 运行测试失败也不是触发宿主重试的理由，否则可能掩盖环境差异。

Docker 先取得本地镜像不可变 ID，再使用无网络、非 root、CPU/内存/PID 限制、只读根文件系统、去能力等参数；工作区绑定的是可写临时副本。容器清理失败会将结论改为 infra_error。隔离有资源与权限约束，但不能宣称对所有内核漏洞提供绝对安全。

宿主后端筛选环境变量、使用副本工作目录，并限制时限与输出；这些不构成文件系统权限隔离。profile 参数数组校验拒绝 shell/内联脚本，也不意味着已登记项目脚本完全可信。

读取结果时至少检查嵌套 `status / exit_code / timed_out / cancelled / truncated / isolated / snapshot_sha256 / cleanup_ok`。`ok=true` 只表示分发取得结构化结果，嵌套 status 仍可能 failed、timeout 或 infra_error。修改代码之后，需要新的版本证据；旧检查通过不能证明后续改动正确。

## 需要懂什么

证据要绑定“输入、环境、执行结果”：快照/补丁摘要识别输入，镜像 ID 与 runtime 识别环境，退出码/日志/清理状态描述执行。只有自然语言“已经测试”缺少这些约束；只有哈希也不证明逻辑正确，仍依赖检查覆盖。

独立 acceptance 与模型能看到的测试分开，减少模型通过改测试自证成功。它仍不能覆盖所有真实使用场景，也不能把小型合成任务的成绩直接外推生产能力。性能收益需要另外测量，本材料不提供未经执行的数字。

## 需要记住什么

- 普通 profile 检查当前快照；固定任务验收检查从基线重建的补丁与独立用例。
- host＝生命周期控制；docker＝额外隔离约束；auto 降级必须显式反映证据级别。
- 工具成功、命令成功、测试通过、任务正确是逐层不同的结论。
