# C05 上下文压缩：原文留存，按安全边界生成请求视图

> 课程性质：核心
> 返回：[导学](../PatchPilot/导学.md)；前置：[C02](02-模型与工具循环.md)、[C04](04-会话持久化与恢复.md)；下一课：[C06](06-长期记忆.md)。
> 对应：B3；[Q4](../PatchPilot/面经.md#q4-长会话的压缩与恢复)；目标掌握：理解机制、设计与表达。

## 本课重点

长会话接近上下文限制时，不直接删除原文，也不从任意字符位置截断聊天消息。会话保留完整 `messages`，另存摘要块，用原始范围与内容摘要关联；模型请求使用“摘要块＋未压缩尾部＋附加来源”的视图。

默认达到可用历史字符预算的 80% 时尝试压缩，目标为 60%；最近 6 条消息、当前用户轮和未完成工具往返受保护。60% 是尽量达到的目标，最终不能超过可用预算才是硬检查。一次请求过大但没有合法旧轮次可压缩时，会停止而非破坏协议。

## 主链与职责

`AgentLoop._call_model → ContextBuilder.build → 扣除 system/tools/附加来源 → HistoryCompactor.compact → 内部摘要请求 → 暂存块与可能的合并块 → 校验视图大小 → 提交 blocks → 最终请求大小检查`。

自动摘要调用复用主模型，通过循环的辅助调用路径共享预算；手动 `/compact` 是独立操作，重新建立本次操作预算，但与提交受同一操作锁约束。两者都不会把摘要请求当成普通聊天指令写进原始历史。

真实的提交边界是：

```python
staged = list(self.blocks)
# 摘要、合并、长度检查全部针对 staged
...
self.blocks = staged
```

后续某个摘要为空、超长、无缩减或调用失败，就不走最后赋值，之前已经提交的 blocks 保留，原文也不变。已发生的模型调用和计费不会回滚。这里是内存摘要状态的提交语义，不是外部服务事务。

## 机制与边界

`_boundaries` 只有在遇到新的普通 user 消息、且 pending 为空时才产生旧轮次结束边界。工具结果也用 user 角色承载，因此不能仅按 role 切分。当前用户轮没有后续新 user 边界，不会进入旧摘要。`preserve_recent=6` 的单位是消息，完整轮次保护可能使实际保留更多消息。

压缩按体积聚合旧轮次，避免每个短轮次都消耗一次摘要请求。活跃摘要块达到 4 个时尝试合并，父块引用所有当前活跃子块，层级最多标记为 3；层级封顶不代表最多只能压缩三次。恢复校验范围连续、边界合法、digest 匹配和 children 关系，阻止摘要绑定到已变化的原文。

摘要消息标为历史数据；保留目标、约束、路径、修改、验证与未知状态是提示协议的要求，仍不能保证模型语义完全无损。最近 thinking/签名块在原文尾部完整保留，旧片段摘要不复述密文；摘要请求本身也需满足上下文限制。

[HTML 专题：切换可压缩轮次、受保护内容过大与摘要失败](topics/C05-上下文压缩.html)展示三种结果。示意数据用于解释分支，不是实测压缩率。

## 需要懂什么

原文是事实来源，摘要是有损的请求视图；检索原文、解压引用不会让摘要自动变成无损编码。`decompress` 返回副本，不改变活跃视图。自动压缩控制输入规模，但摘要调用本身也消耗模型预算与时间，预算接近耗尽时可能先停在摘要阶段。

当前容量单位是 Python 字符序列化长度，不能保证对应某模型的 tokenizer 上限；记忆消息拼接和评估二次 JSON 包装都可能增加开销，因此构建完成后还要总量检查。若改为精确 token 预算，需要 Provider 对应的计量策略和额外预留，属于进阶方案。

## 需要记住什么

- 默认 0.8 触发、0.6 目标、最近 6 条消息；都受完整轮次边界约束。
- 摘要块绑定 `[start,end)` 原文和 digest；活跃块替换原文范围生成视图，原始历史保留。
- 摘要失败不提交新 blocks；近期内容无法折叠就停止；不是所有超限都能靠压缩解决。
