# C09 任务服务与租约：旧 Worker 为什么失去提交权

> 课程性质：核心
> 返回：[导学](../PatchPilot/导学.md)；前置：[C04](04-会话持久化与恢复.md)、[C07](07-目标续跑与共享预算.md)、[C08](08-代码验证与证据.md)；下一课：[C10](10-评测与工程质量.md)。
> 对应：B6；[Q8](../PatchPilot/面经.md#q8-worker-失联后的提交权)；目标掌握：理解机制、设计与表达。

## 本课重点

Worker A 执行中失联，不能因为它稍后拿到一个成功结果就允许覆盖当前任务。数据库写入同时检查当前 attempt、Worker、随机 token、状态和数据库时钟下的租约；心跳、事件、步骤、检查点、产物登记和终态提交都经过租约边界。

运行级 Run 与执行尝试 Attempt 分开。过期回收将运行置 interrupted（取消场景置 cancelled），并不自动重新入队；显式 restart 才回到 queued，后续领取创建新 Attempt。

## 主链与职责

`Bearer API 创建 Run → 数据库 queued → claim 短事务领取 → 心跳线程 → 执行器 → 完整工具批次边界保存补丁检查点 → 验收 → finalize → 完成`。

API 不在请求里同步执行修复；Worker 独立运行。数据库是调度状态权威，文件存储保存 sealed 内容，公开访问通过数据库产物引用控制。execution_status 与 verdict 分开，执行完成不等于验收通过。

领取使用 `SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1`，在同一事务里创建 attempt 和更新 current_attempt。事务完成后开始长任务，不在整个模型调用期间持有领取行锁。其他 Worker 跳过已锁定队列项，避免等待同一个领取事务。

## 机制与边界

`_fence` 统一按 Run→Attempt 顺序加锁，等待锁后取数据库 `clock_timestamp()`，再校验租约。使用数据库时钟减少不同 Worker 本地时钟漂移影响；锁顺序减少与回收器的反向死锁。随机 token 配合当前 attempt 身份阻止旧凭证写入，不能称为单调递增 fencing number。

心跳不能复活已经过期的租约：它先走 `_fence`，有效才延期。心跳返回取消请求时停止本地控制器；租约丢失同样停止。取消是合作式的，数据库标志与真正停止之间存在时间窗口，最终提交时还会检查取消，避免迟到成功覆盖已接受取消。

`finalize` 锁内先检查租约和取消，再让回调封存与有效终态一致的报告，随后再次查数据库时钟/租约，登记报告并提交终态。若报告写入耗尽租约，数据库事务回滚；文件系统可能留下未登记文件，因为它不是数据库事务的一部分。

服务检查点保存从任务基线导出的累计补丁、基线/候选摘要及计数元数据；重启从最新检查点恢复候选代码并核对摘要。它不保存完整模型对话、推理状态或全量宿主进程。外部模型请求可能在失租前已被服务端处理，数据库 fence 无法追回费用，更不能证明所有副作用恰好一次。

## 需要懂什么

领取互斥与执行所有权是两个阶段：行锁保护领取事务，租约与身份校验保护后续多次写入。只加 SKIP LOCKED，无法防止一个失联 Worker 回来提交旧结果；只设心跳，不在写入时检查，也挡不住过期请求。

若进一步控制外部副作用，需要动作幂等键、远端查询与补偿，或者把动作纳入能验证 epoch 的服务。当前服务主要保证受 fence 保护的数据库状态不被旧尝试更新，没有通用分布式恰好一次协议。

## 需要记住什么

- `queued → running → completed/failed/interrupted/cancelled`；只有 interrupted/failed 可显式 restart。
- 领取事务短；每次写入重新检查当前 attempt、Worker、随机 token、状态、DB 时间租约。
- 补丁检查点不等于聊天状态；文件封存不等于数据库登记；fence 不等于撤销外部动作。
